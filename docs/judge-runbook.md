# Judge runbook - MANDATE

## Fast path (about 2 minutes, no wallet required)

1. Open <https://mandate-bnb-agent.vercel.app>.
2. Enter: `Earn on 5,000 USDT. No leverage. Low risk. Max 3 actions per week. Allowed protocols: Venus, Lista.`
3. Edit one field from the right-hand mandate preview and confirm the natural-language mandate updates.
4. Select **Create mandate** and confirm the page stays in the builder with a **Mandate created** receipt. Then select **Search marketplace**.
5. Confirm the hireable table contains only identities with a public ERC-8004 receipt. Unverified comparison fixtures are withheld rather than shown as APY/PnL/count history.
6. Inspect **Agents found across the open registry** at the top of the results and confirm it returns live external BNB Chain ERC-8004 records independently from MANDATE's verified execution providers.
7. Open an external result, review its onchain identity, declared HTTPS service, endpoint verification signal and unproven financial limits. If the endpoint is callable, request signed acceptance; MANDATE tries its small acceptance schema and then the official BNBAgent A2A `message/send` negotiation path (resolving the agent card and its advertised skill first). Confirm the provider wallet, request hash, signed quote, chain/Commerce binding and 0.1 U ceiling are checked. Offline or malformed endpoints fall back to **Invite with Open Mandate**; assignment stays locked without the verified signature.
8. Run live YieldRoute. This is read-only and requests no wallet signature.
9. Run the live read-only capability, confirm the hash and source, then open Review permissions and confirm that capital, risk, leverage, protocol, activity and service-spend limits match the original mandate.
10. Continue to the onchain hire page. Without signing, inspect the separate client/provider roles and seven-step ERC-8183 lifecycle.
11. Open Evidence and inspect the final hire-backed Agent Advantage Report. Confirm its three completed jobs (#642, #644, #666), paired raw outputs, timings, costs, quality scores and limitations.
12. Open **Add independent provider** and inspect the wallet-separated onboarding flow. It must require a second wallet, a provider-controlled `mandate.provider-service.v1` document, and a successful provider-signed BSC Testnet execution receipt before adding an identity to the callable inventory; it must never request a seed phrase.
13. On a funded external job, use **Request bounded execution**. If the Agent Card advertises `notify_funded`, confirm the provider acknowledges the official handoff and then submit its own result onchain; otherwise confirm the provider's signed execution receipt is checked against `from`, `to`, calldata, value, allowlist and chain 97. If the provider also returns an ERC-8183 submit receipt, the job refreshes to SUBMITTED without a buyer-side fake deliverable.
14. In the Grid live result, inspect the paper record's risk exposure and the explicit empty onchain-trading evidence set. Do not call the paper win rate realized trading performance. A realized record is only shown when a provider publishes receipt-linked trades.

## Hard no-match path (about 1 minute, no wallet required)

1. Enter: `Earn on 5,000 USDT. No leverage. Low risk. Max 1 action per month. Allowed protocols: Aster. Spend no more than $0.01 total.`
2. Build the mandate, then search the marketplace.
3. Confirm all disclosed candidates are **Excluded**, with exact rejection reasons and no recommended agent.
4. Select **Publish open mandate**. Confirm the brief is unchanged, Provider is **UNASSIGNED**, escrow is **0 U**, and publication requires only a BSC Testnet `createJob` signature.
5. Do not sign during the fast demo. This screen is the inspectable proof that a user specification is independent from provider discovery; a confirmed publication creates a real unfunded ERC-8183 job.
